# 과제 05: 순차 탐색과 이진 탐색 트리 비교

## 1.

숫자 비교 횟수는 찾는 값을 배열 원소(또는 트리 노드)와 한 번 비교할 때마다 1번으로 세었습니다.

## 2. 실행 결과

| | 순차 탐색 | BST 탐색 |
|---|---|---|
| 총 비교 횟수 (50번 탐색) | 4,823 | 442 |
| 평균 비교 횟수 | 96.46 | 8.84 |

- BST를 만들 때 비교한 횟수: **703번**
- 탐색 성공 4번, 실패 46번 / 트리 높이 15

## 3. 분석

**탐색 성능 차이**
BST 탐색이 평균 8.84번으로 순차 탐색(96.46번)보다 약 10배 적었습니다. 순차 탐색은 값이 없으면 100개를 끝까지 봐야 하지만, BST는 비교할 때마다 한쪽만 보면 되므로 트리 높이(15)만큼만 내려가기 때문입니다.

**BST 만드는 비용을 포함하면**
BST를 만들 때 703번 비교했습니다. 이를 더해도 BST는 703 + 442 = 1,145번이고 순차 탐색은 4,823번이라서 BST가 더 적습니다. 약 8번 이상 탐색하면 만드는 비용을 채울 수 있습니다. 탐색을 1~2번만 한다면 순차 탐색이 더 낫습니다.

**트리 모양에 따른 차이**
이번에는 숫자가 랜덤하게 들어와서 높이 15의 트리가 되었습니다. 만약 작은 숫자부터 순서대로 들어오면 계속 오른쪽에만 붙어서 트리가 한 줄이 되고, 높이가 100이 되어 탐색이 순차 탐색처럼 느려집니다. 이때 만드는 비교 횟수도 0 + 1 + ... + 99 = 4,950번(직접 계산한 값)으로, 순차 탐색 전체(4,823번)보다 많아집니다.

## 4. 결론

BST는 비교 횟수가 훨씬 적고 만드는 비용을 더해도 이득이지만, 트리가 한쪽으로 치우치면 이 장점이 사라집니다.
